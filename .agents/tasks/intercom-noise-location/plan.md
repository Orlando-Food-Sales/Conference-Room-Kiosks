## Design decisions (the open points)

**Carrying the call: WebRTC, tablet to dashboard, audio peer to peer; server only relays setup messages.**
- Why: no npm dependency, no audio ever passes through or touches the server, so nothing can be stored or logged by it. A WebSocket audio relay would put sound on the server and need a hand-written WebSocket server.
- Signalling: tablet to server by POST (public routes, like `/api/tablets/heartbeat`). Server to tablet by the existing SSE stream, but only to the one tablet (new `notifyTablet`, matching `tabletId`), because `notifyRoom` also reaches the public `room=*` stream and must not carry call data. Dashboard to server by POST under `/api/admin/` (existing auth). Server to dashboard by a new admin-only SSE stream `GET /api/admin/intercom/stream`, read in the dashboard with `fetch` + a stream reader (EventSource cannot send the `Authorization` header that token mode needs).
- No STUN/TURN: `iceServers: []`, LAN host candidates only. Works for an admin on the office network or VPN with UDP allowed; an admin on a different network may get "could not connect". Documented as a limitation. Not adding an env switch (YAGNI).

**Call sequence (the person at the door always starts it; nothing on the admin side can start one).**
1. Door person presses the new "Call" button. Tablet POSTs `/api/intercom/ring {roomId, tabletId}`. No microphone has been opened and no `RTCPeerConnection` exists yet.
2. Server: if no admin dashboard stream is open, answers `{state:'nobody'}` and creates no call; tablet shows "Nobody is signed in to the dashboard right now. Please try again or knock." Otherwise it creates a call (random 16-byte hex `callId`, separate `token` returned only to that tablet), sends `ring` to every admin stream, and the tablet shows "Calling… please wait".
3. An admin presses Answer (inside a click, so the browser can ask for the microphone). `POST /api/admin/intercom/answer {callId, client}`: first admin wins; a second gets 409 "Already answered by <who>" and its banner clears (admins get a `taken` event). Server logs the answerer and sends the tablet an `intercom` event `{state:'answered'}`.
4. Only now the tablet calls `getUserMedia({audio})`, shows the red "Microphone on" badge, creates the peer connection and offer, and POSTs it to `/api/intercom/signal`. The server forwards to the answering admin only. The admin opens its own microphone, answers, and ICE candidates go both ways. The tablet's mic track stays `enabled=false` until the peer connection state is `connected`. The tablet then shows "Connected" and the admin "Talking with <room>".
5. Either side hangs up (`/api/intercom/hangup` with token, `/api/admin/intercom/hangup`). The tablet stops every track, closes the connection, hides the badge. Server also ends the call after 10 minutes, or if the answering admin's stream closes.
- Door person sees: "Calling…", "Connecting…", "Connected" (with Hang up), "Nobody answered. Please knock or try again." (ring timeout 45 s, `INTERCOM_RING_SECONDS`), "Call ended", "Could not start the microphone" (and the server is told to end the call).
- Busy: one call per room at a time; a second press while one is active gets 409 "Someone is already calling" (the tablet shows the call state it already has). A 3 s cooldown after a call ends stops button hammering.
- Nobody on the dashboard / two admins: handled in steps 2 and 3. A forgotten open dashboard tab rings and simply times out as "unanswered".
- Ring alert for admins: a large banner with room name and Answer / Not now buttons, page title flashing, and a short tone from WebAudio that may be blocked until the page has had a click (best effort; the banner always shows). No Teams or webhook alert: a call is live, an alert after the fact is useless, and `deliver()` is for problems.

**Badge and logging (the camera pattern).** Tablet: new `#micNotice` element (red pill like `.camera-notice`, text "● Microphone on") shown while the tablet's own microphone stream is live (shown/hidden by the tablet from its real track state, not from a server promise), plus a server `intercom` SSE event for the call panel text. Log lines with who, never any SDP or sound: `Intercom: call from Front Conference Room started at the door`, `Intercom: Front Conference Room answered by <email|the administrator token>`, `Intercom: Front Conference Room call ended after N s (<hung up at the door|hung up by <who>|nobody answered|no administrator on the dashboard|timed out>)`.

**Noise.** The tablet measures the level itself with a Web Audio `AnalyserNode` on a microphone stream (constraints echoCancellation/noiseSuppression/autoGainControl all false, otherwise the processing flattens the level). Nothing but a number leaves the tablet. It is not "silent": a small grey pill `#noiseNotice` ("◐ Noise meter on (no sound is sent or kept)") is visible on the tablet whenever the meter runs.
- Level per 1 s block = RMS in dBFS. A report covers 10 s: the third loudest of the ten blocks, so one door slam does not count but steady talking does. Levels: `quiet` below `NOISE_TALKING_DB` (default -50), `talking` up to `NOISE_LOUD_DB` (default -35), `loud` above. The thresholds are guesses until measured on a real tablet, so the report also carries the dB number (an integer) and the dashboard shows it ("talking (-43 dB)") to tune the two env values.
- Continuous or not: only while the page is visible, the display is not switched off (`control.displayEnabled !== false`), and no call is running (the meter stops when a call starts and restarts after). Off for `?nostream=1` previews. `NOISE_METER=off` turns it off server-wide (sent to tablets in `/api/config`).
- Sent with the heartbeat (`noise: {level, db}`, or `noise: null` plus `noiseStatus` when not measuring); a changed level triggers an extra heartbeat right away (at most one per 10 s). The dashboard shows the reading only if under 2 minutes old, else "noise not measured".
- No alerts for noise (it is a live "is it loud now" glance, a threshold alert would be noise itself).

**Location.** Browser `navigator.geolocation.getCurrentPosition` (needs https and Fully's geolocation access, which is already on, plus Android's own location switch and Fully's Android location permission). Read once at page start and refreshed every 6 hours (a wall tablet does not move; no watch, no battery drain), low accuracy, 20 s timeout. Sent with the heartbeat as `location: {lat, lon, accuracy}` rounded to 5 decimals, or `locationStatus` (`denied`, `unavailable`, `insecure`, `timeout`) when there is none. No Fully-specific API is used: the repo has no evidence of one and I will not plan on a guess.
- Dashboard shows `Location: 40.95950, -74.12520 (within 35 m) · Open map` where "Open map" is a link to `https://www.openstreetmap.org/?mlat=LAT&mlon=LON#map=18/LAT/LON` (`target=_blank rel=noopener`; nothing is fetched unless the admin clicks; CSP unaffected). When the tablet cannot say: "Location not reported (<plain reason>)". `LOCATION_REPORT=off` turns it off.
- No alert on location. A moved or stolen tablet alert would be useful but is outside the request; mention as a possible follow-up only.

**Secure page.** Browsers only allow microphone and location on https/localhost. The server already serves everything on https (template `deploy/nginx-https.conf` proxies `/` on both ports), so no nginx change is needed for it to work, and the redirect for tablets is left off so tablets not yet switched keep working and a rollback needs no server change. Code changes: `Permissions-Policy` in `src/server.js` currently says `microphone=(), geolocation=()`, which blocks both even on https; change to `camera=(), microphone=(self), geolocation=(self)`. CSP needs no change (WebRTC media is not governed by `connect-src`/`media-src`; the dashboard uses `srcObject`). The tablet reports `secure: window.isSecureContext` in the heartbeat; over plain http the call button, noise meter and location stay off and the dashboard shows "this tablet is on plain http: intercom, noise and location need https". Docs tell him the new Fully Start URLs: `https://conference.orlandofoods.com/room/front?kiosk=1` and `.../room/back?kiosk=1`.

**Config (`src/config.js`, `.env.example`).** `INTERCOM_ENABLED` (default on), `INTERCOM_RING_SECONDS` (45, 10-120), `INTERCOM_MAX_MINUTES` (10, 1-60), `NOISE_METER` (default on), `NOISE_TALKING_DB` (-50), `NOISE_LOUD_DB` (-35, must be above talking, else a settings problem that turns the meter off and is logged, same style as `config.camera.problem`), `LOCATION_REPORT` (default on). Resulting `config.intercom`, `config.noise`, `config.location`.
